题目：基于大模型与知识图谱的智能教学系统设计与实现

建议时长：8-10 分钟

## 第 1 页：标题页

页面内容：

- 基于大模型与知识图谱的智能教学系统设计与实现
- 夏宇晗 / 计算机科学与技术
- 指导教师：郑炜 教授

讲稿：

各位老师好，我是夏宇晗。我的毕业设计题目是《基于大模型与知识图谱的智能教学系统设计与实现》。本课题不是单纯做一个聊天问答页面，而是围绕教材学习场景，设计并实现了一个包含教材资源管理、PDF 解析、RAG 问答、知识图谱、知识点学习和权限控制的完整教学平台。下面我将从研究背景、系统设计、关键实现、测试结果和总结展望五个方面进行汇报。

## 第 2 页：研究背景与痛点

页面内容：

- 传统教学平台偏“文件管理”，缺少教材深层理解。
- 学生难以把握章节逻辑、知识点依赖和跨资源关联。
- 通用大模型问答容易脱离教材语境，存在幻觉风险。
- 教师需要统一管理教材、视频、资料和访问权限。

讲稿：

当前很多在线教学平台主要解决的是资源上传、在线播放和基础检索问题，本质上还是文件库。随着教材、视频和补充资料越来越多，学生面临的问题不是“有没有资源”，而是“如何理解资源之间的结构”。同时，如果直接把通用大模型接入教学场景，它可能脱离教材内容泛泛回答，甚至出现事实幻觉。因此，本课题希望把大模型能力放进一个受教材上下文约束的教学系统里，让问答、图谱和资源管理形成闭环。

## 第 3 页：课题目标与系统定位

页面内容：

- 目标：构建以教材为核心的混合式智能教学平台。
- 教师端：教材上传、资源管理、权限配置。
- 学生端：教材阅读、智能问答、知识图谱、知识点学习。
- AI 能力：检索增强生成、多轮对话记忆、知识点上下文问答。

讲稿：

本系统的定位是“以教材为核心”的混合式教学平台。教师端负责上传教材、管理视频和资料，并配置学生访问权限；学生端则围绕教材进行阅读、提问和图谱浏览。AI 能力并不是孤立存在，而是嵌入教材处理链路中：系统先解析教材，再进行向量化检索和知识图谱构建，最终支撑学生在教材层级和知识点层级进行问答。

## 第 4 页：系统总体架构

页面内容：

- 前端：React + TypeScript + Webpack。
- 后端：Go + Gin，负责业务接口和 AI 编排。
- MySQL：用户、教材、资源、知识点元数据。
- MongoDB：教材解析内容和聊天历史。
- Qdrant：教材文本向量检索。
- Neo4j：知识点与依赖关系。
- Docker Compose：统一部署。

讲稿：

系统采用前后端分离和容器化部署架构。前端使用 React 实现教师端、学生端、教材详情页和知识点详情页；后端使用 Go 和 Gin 提供接口，并负责编排教材解析、向量检索、大模型调用和图谱构建。存储层采用多数据库协同：MySQL 保存结构化元数据，MongoDB 保存教材解析结果和对话历史，Qdrant 支持语义检索，Neo4j 保存知识点关系。通过 Docker Compose，可以在本地或服务器上统一启动所有服务。

## 第 5 页：教材处理与 RAG 问答流程

页面内容：

- 教材上传后进入解析状态。
- PDF 文本提取并按章节、段落入库 MongoDB。
- 文本切块后写入 Qdrant 向量库。
- 提问时检索相关片段，组装教材上下文。
- SSE 流式返回 Markdown 答案，并保存多轮历史。

讲稿：

教材处理是系统的核心链路。教师上传 PDF 后，后端先保存教材元数据，然后异步进行 PDF 解析。解析结果会写入 MongoDB，方便前端展示 AI 解析文稿；同时系统会把教材文本切块并写入 Qdrant。学生提问时，系统先根据问题检索相关教材片段，再把片段、历史对话和当前问题一起组织成 Prompt，调用大模型生成答案。答案通过 SSE 流式返回，前端可以边生成边展示，并支持 Markdown 渲染。

## 第 6 页：知识图谱构建与知识点学习

页面内容：

- 大模型抽取核心知识点、总结和前置关系。
- MySQL 保存知识点详情，Neo4j 保存图关系。
- 前端使用力导向图展示知识结构。
- 支持点击节点进入知识点详情页。
- 知识点学习助手围绕当前知识点进行问答。

讲稿：

除了问答，本系统还构建了教材知识图谱。系统会根据教材内容调用大模型抽取核心知识点、知识点总结和前置依赖关系。这里采用了 MySQL 和 Neo4j 双写设计：MySQL 便于业务查询和详情页展示，Neo4j 负责图结构存储和关系查询。前端使用力导向图展示知识点网络，并针对缩放场景做了分级渲染，避免节点过密时文字重叠。学生可以点击图谱中的知识点进入详情页，并使用知识点学习助手进行更聚焦的问答。

## 第 7 页：教师端与学生端功能闭环

页面内容：

- 教师端：创建教材、上传资源、删除资源、配置 ACL。
- 学生端：查看授权教材、阅读 PDF、查看解析文稿、浏览图谱。
- 教材资源：视频、资料、知识点专属资源。
- 页面路径：教材列表 -> 教材详情 -> 知识点详情。

讲稿：

在业务功能上，系统形成了教师端和学生端的闭环。教师可以创建教材、上传 PDF、关联视频和资料，还可以配置教材的公开或私有访问权限。学生登录后只能看到自己有权限访问的教材，并可以进入教材详情页阅读 PDF、查看解析文稿、使用问答助手和浏览知识图谱。知识点详情页进一步支持知识点专属视频和资料，使资源组织从“教材级”细化到“知识点级”。

## 第 8 页：权限控制与工程可靠性

页面内容：

- JWT 登录认证与角色隔离。
- 教材级 ACL：公开教材 / 私有教材 / 学生白名单。
- 权限校验覆盖列表、搜索、详情、问答、资源上传。
- 大文件上传上限调整至 200MB。
- 容器化部署区分本地演示和服务器生产配置。

讲稿：

教学平台不仅要能展示功能，还要保证权限边界。系统使用 JWT 进行登录认证，并区分教师和学生角色。教材权限支持公开和私有两种模式，私有教材可以配置学生 ID 白名单。权限控制不是只在前端隐藏按钮，而是在后端列表、搜索、详情、知识点详情、问答和资源上传等接口中统一校验。工程可靠性方面，系统修复了大文件上传 413、教材状态提前完成、图谱缩放重叠等问题，并通过 Docker Compose 保证部署环境一致。

## 可能问答

### 问：为什么同时使用 MySQL、MongoDB、Qdrant 和 Neo4j？

答：因为系统数据形态不同。MySQL 适合用户、教材、资源和权限等结构化元数据；MongoDB 适合保存教材解析后的章节内容和多轮聊天历史；Qdrant 用于向量检索；Neo4j 用于保存知识点和依赖关系。分开存储可以让每类数据使用更适合的查询方式。

### 问：系统如何减少大模型幻觉？

答：系统不是直接把用户问题交给大模型，而是先从 Qdrant 检索教材相关片段，并结合教材内容、历史对话和知识点上下文组织 Prompt。这样回答会尽量锚定当前教材语境，降低开放域泛化回答带来的幻觉风险。

### 问：知识图谱构建为什么耗时较长？

答：知识图谱构建需要从教材长文本中抽取知识点、总结内容并识别前置关系，这一阶段涉及多次大模型调用，所以耗时明显高于普通解析和向量写入。系统针对大教材采用自适应抽取策略，优先保留主干知识点，控制节点数量和调用成本。

### 问：权限控制是否只靠前端隐藏？

答：不是。前端会根据角色隐藏部分状态和按钮，但真正的权限控制在后端完成，覆盖教材列表、搜索、详情、知识点详情、问答和资源上传等入口。测试中 37 个权限用例全部通过。

### 问：和普通大模型问答 Demo 的区别是什么？

答：普通 Demo 往往只有输入问题和输出答案。本系统围绕教学场景实现了教材上传、PDF 解析、向量检索、图谱构建、资源管理、权限控制和历史记忆，重点是让大模型能力和教学资源、用户身份、知识结构稳定关联。
